What are we doing?

This practical demonstrates how a JavaScript application can interact with Ethereum using ethers.js and MetaMask.

The application never receives your private key. MetaMask controls the account and asks the user to approve/sign transactions.

Key Concepts

  • 1 SepETH = 1018 wei for denomination/conversion purposes.
  • ethers.parseEther("0.1") converts 0.1 SepETH into 100000000000000000 wei.
  • The Provider gives the application access to Ethereum.
  • The Signer represents the currently authorized MetaMask account.
  • The private key remains protected by MetaMask.
  • The receiver needs only a valid Ethereum address.
  • The sender transfers SepETH and also pays the transaction gas fee.
  • The receiver receives the transferred SepETH and does not pay the sender's gas.
  • Changing the active MetaMask account changes the transaction Signer / Sender. The dApp revalidates and refreshes the sender before another transaction can be prepared.
  • The application locks the Send button as soon as a transaction request begins, preventing accidental duplicate submission from repeated clicks.
  • A transaction hash uniquely identifies the submitted Ethereum transaction.
  • This application allows transactions only after verifying Sepolia Chain ID 11155111.
